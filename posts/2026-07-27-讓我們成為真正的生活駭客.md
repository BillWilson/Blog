# 讓我們成為真正的生活駭客：當 Agent 成為現實世界的 Design Pattern (Agentic as a Real-World Design Pattern)

> 🇬🇧 English version: [Design Patterns Finally Escaped the Screen](https://yhhbill.dev/posts/2026-07-27-design-patterns-finally-escaped-the-screen/)

最近參加了 HappyDesigner 七月場「Agents, Agents, Agents」，聽了一晚關於不同產業導入 AI agent 的精彩分享。在有限的時間中，分享的內容有如濃縮高湯一樣，每一段故事都是滿滿的細節。

在聽完這些截然不同的場景領域後，我一直在想：為什麼這些產業成功導入的做法，核心概念看起來卻如此相似？後來我突然意識到，因為 agent 不只是一項產品，它更像是軟體圈說的 Design Pattern（設計模式）：一種被反覆驗證、可以照著套用的解題套路。而且，這是設計模式第一次開始被實作在實體世界中。

有趣的是，設計模式這個概念最早並不是軟體業發明的。軟體圈的經典《Design Patterns》有四位作者，人稱 GoF（Gang of Four），而這個概念是他們跟建築師 Christopher Alexander 借來的。Alexander 在《A Pattern Language》裡研究城市與房子時寫道：

> Each pattern describes a problem which occurs over and over again in our environment, and then describes the core of the solution to that problem.

意思是：每個模式描述的，是一個在我們的環境中反覆出現的問題，以及這個問題的解法核心。軟體業花了十七年把這套思維從建築帶進程式碼，而現在，agent 似乎正在把它還給實體世界。

紡織廠的案例蠻貼切地點出了這個概念，分享者是離開 LINE 後創業、專注傳產 AI 導入的 Albert Chen。一張過去需要人工翻譯、手動剪貼三小時的海外需求單，現在透過 agent 三分鐘就能搞定。Albert 提到，其實兩年前的 AI 模型（Claude 3.5 Sonnet）就做得到，關鍵在於場景。

他們請快退休的老師傅「當 AI 的老師」，用語音錄下畢生的 SOP。這其實就是軟體裡標準的 Strategy Pattern（策略模式），道理跟食譜一模一樣：主廚把手藝寫成食譜，任何廚師照著做都能重現這道菜；換一本食譜，同一個廚房就能出另一道菜。老師傅是寫食譜的人，agent 是照著食譜做菜的廚房。而在這背後支撐的，是把應用場景、輸入、輸出、步驟一一交代清楚的功夫——等於規定好每份食譜都要有的格式——工程圈稱之為 context engineering，只是這次實作的地點不在程式碼裡，而在工廠。

同樣的模式也在數位廣告公司出現。創新技術總監 Blake Pai 寫了一支 agent，每天去巡視其他 agent 的對話，把卡關和被罵的片段收集起來作為改版依據。這對應到軟體裡的 Observer Pattern（觀察者模式），像一位每天巡線的品管員。透過這樣的監聽與回饋，他們讓系統每天進步一點，工程圈把這種讓回饋不斷循環的設計稱為 loop engineering。

至於在 Meta 待了十年的 Principal TPM Aki Chiu，則是實踐最新的 graph engineering，一個設計「指揮者與 AI 協作網路」的學問。Aki 做了三個 bot，分別接走「追進度的他」、「報進度的他」和「被問資訊的他」，等於把過載的自己，拆解重組成一張由人與 AI 一起分工的網路。這網路有清楚的規則：專案資訊全員可讀，寫入權限只留給特定四個人，守住的不只是資料，而是資料的可信度。更關鍵的是，有些行為被刻意拿掉：bot 不能做決策，對外的說法與定調只能出自人類。誰能讀、誰能寫、哪些行為不准存在，設計這網路的形狀本身，正是 graph engineering 的主張。

回頭看這三個場景，沒有人在糾結該用哪一款 AI，他們真正花力氣的，都是把問題的本質弄清楚——只有當理解問題的本質時，我們才可能跳脫出技術選型的框架。

以前我們寫 Go、寫 Python，程式碼執行的環境是伺服器，驅動的是機器；現在，老師傅對著手機口述 SOP，其實他也是在寫 code，只是這段 code 執行的環境，是他待了四十年的那座工廠。

自然語言，正式成為了實體世界專屬的程式語言。

語法的門檻消失了，但工程思維並沒有消失，它變成了三門新功課：把脈絡交代清楚（context）、讓回饋持續發生（loop）、把協作關係設計好（graph）。我們還是在做同一件事，繼續用系統思維去 hack 這個世界。

以前的「生活駭客」是下載各種 App 來優化時間；現在，只要我們能把日常的流程當成一套可以被改寫的程式，所有人都能用自然語言重新設定身邊的現實世界，成為真正的生活駭客。

## 心得 Conclusion

Design pattern 花了十七年從建築走進軟體，
再花三十年從軟體走回實體世界。
這一次 pattern 思維設計的不再只是系統，
還有組織、工廠，以及人與 AI 的關係。

補充當天 open discussion 留下的一題，我覺得會是每個產業接下來的必修題：

> 你有什麼事情想交給 AI agent 做？交給 AI 的條件是什麼？

我的答案是：我想要把各種與「創意」無關的繁瑣工作，全部交給 AI agent。

至於交給它的條件？只要這件事能被清楚定義成一份「食譜」，就該發包出去。因為唯有把時間徹底解放出來，我們才能去做那些真正有價值、充滿創意的工作。

畢竟，我們生來是為了當寫食譜的主廚，而不是永遠待在產線上切菜的人。
